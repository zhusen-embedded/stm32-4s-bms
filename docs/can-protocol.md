# CAN 帧格式

周期 100 ms，标准帧，ID = `0x180 + 板号`，DLC = 8，500 kbps。

| 字节 | 内容 | 编码 | 说明 |
|---|---|---|---|
| 0-1 | 总压 | `uint16`，0.01 V/bit | 小端。3.7×4=14.8 V → 1480 |
| 2-3 | 电流 | `int16`，0.01 A/bit | 小端，放电为正。充电 -2.5 A → -250 |
| 4 | 温度 | `uint8`，偏移 +40 | 见下 |
| 5 | SOC | `uint8`，1 %/bit | 0~100 |
| 6-7 | 故障码 | `uint16` 位域 | 见下 |

## 温度为什么用偏移

温度可能是负的，但字段只有一个字节。直接 `(uint8_t)(-5.0f)` 会变成 251，接收端解出 251 ℃。

偏移 40 之后：

- -40 ℃ → 0
- 0 ℃ → 40
- 25 ℃ → 65
- 65 ℃（过温阈值）→ 105

-40 到 +215 ℃ 都能表示，电池场景完全够。

接收端解回来：`temp = raw - 40`。

## 故障码位定义

| bit | 含义 | 触发条件 |
|---|---|---|
| 0 | 过压 OV | 任一节 > 4250 mV |
| 1 | 欠压 UV | 任一节 < 2800 mV |
| 2 | 过流 OC | 电流 > 20 A |
| 3 | 过温 OT | 温度 > 65 ℃ |
| 4-15 | 保留 | — |

故障是**锁存**的：一旦置位就保持，必须显式清（上位机发命令，或者断电重启）才能恢复。这样设计是为了防止「过温 → 保护断开 → 温度降下来 → 自动恢复 → 又过温」这种反复通断，对 MOS 和电池都不好。

## 为什么选这些分辨率

- **总压 0.01 V**：4 节 18650 满电 16.8 V，用 `uint16` 表示到 655.35 V，分辨率 10 mV。看起来浪费，但 0.1 V 分辨率太粗（充满和接近充满分不出来），0.001 V 又要 32 位。0.01 V 是个折中。
- **电流 0.01 A**：这个项目电流范围是 ±20 A，0.01 A 分辨率够了。如果做电动车那种上百安的，就得换 0.1 A。
- **SOC 1%**：本来 SOC 估算精度也就 ±3%，报 0.1% 是自欺欺人。

## 接收端示例

```c
typedef struct {
    float vpack;
    float current;
    float temp;
    uint8_t soc;
    uint16_t fault;
} can_status_t;

void can_unpack(const uint8_t d[8], can_status_t *st) {
    st->vpack   = (float)((uint16_t)d[0] | ((uint16_t)d[1] << 8)) * 0.01f;
    st->current = (float)(int16_t)((uint16_t)d[2] | ((uint16_t)d[3] << 8)) * 0.01f;
    st->temp    = (float)d[4] - 40.0f;
    st->soc     = d[5];
    st->fault   = (uint16_t)d[6] | ((uint16_t)d[7] << 8);
}
```

## 还没做的

- **没有心跳帧**。如果 BMS 挂了，接收端只会发现「没数据了」，但分不清是 BMS 死了还是 CAN 线断了。加个周期性的心跳帧会好一些。
- **没有命令帧**。清故障、读详细数据、改参数这些都需要下行通道，现在只有上行。
- **没有多板 ID 分配机制**。`0x180 + 板号` 里的板号是写死的，多板并联的话要改成拨码或者软件分配。

这些等单板跑通了再加。
