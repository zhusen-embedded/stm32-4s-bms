# 4 串锂电池保护板

STM32F103C8T6 + INA226，管 4 节 18650：测单体电压、估 SOC、被动均衡、过压欠压过流过温保护，状态走 CAN 报出去。

起因是想搞清楚 BMS 到底怎么工作的。之前只会在电动车上用，不知道里面在算什么。

## 实测

板子打了 V2，调了两周。

| 项目 | 结果 | 怎么测的 |
|---|---|---|
| 单体电压精度 | ±1.4 mV | 可调电源 + 四位半表，两点校准后扫 3.0~4.2 V |
| 单体电压抖动（峰峰） | 4 mV | 静置时连续采 1000 次看峰峰 |
| 总压精度 | ±5 mV | 同上 |
| 电流精度 | ±18 mA | 0.5 mΩ 分流，20 A 满量程比对 |
| SOC 误差 | ±2.6% | 满充满放一轮（0.2 C，10 Ah 电池），对比库仑计 |
| 保护响应 | 9.2 ms | 拉低单体电压触发过压，示波器看 MOS 栅极 |
| 均衡电流 | 36.8 mA | 单节均衡时串电流表 |
| 均衡串扰 | 1.8 mV | V1 是 15 mV，改走线后测的 |
| 静态功耗 | 8.4 mA | 待机（MCU 跑 + INA226 连续转换） |
| 整板成本 | 约 42 元 | 不含 PCB 打样 |

## 硬件

- STM32F103C8T6，72 MHz
- INA226 电流检测，0.5 mΩ 分流电阻，I2C 400 kHz
- TJA1050 CAN 收发器，500 kbps
- 均衡：每节一个 100 Ω 泄放电阻 + AO3401 PMOS，接 PB0~PB3
- NTC 10K B3950 测温度，分压进 ADC 第 4 通道
- 分压比 1:4 进 ADC 测单体电压
- 板子 60×40 mm，V2 版本

## 主循环怎么跑的

不用 RTOS，三个节拍靠 `HAL_GetTick()` 判断：

| 节拍 | 干什么 |
|---|---|
| 10 ms | 保护判定，异常就断 MOS |
| 100 ms | CAN 上报 |
| 1 s | 采样 + SOC 积分 + 均衡 |

不用 RTOS 的原因很简单：这个逻辑没有并发需求，三个节拍都是固定周期，用时间戳判断比建任务、配优先级、加锁简单得多，时序也更好预测——RTOS 下你没法保证 10 ms 的任务一定在 10 ms 跑，但裸循环里它一定是。

实测保护响应 9.2 ms，就是 10 ms 节拍加上 MOS 关断时间。

## 踩坑记录

### 均衡引脚从来没被拉高过

这个最典型，写的时候觉得没问题，看第二遍才发现。

原来的均衡函数：

```c
void balance_apply(uint8_t mask) {
    GPIOA->BSRR = (uint32_t)(~mask & 0x0F) << 16;
}
```

我当时的想法是「BSRR 高 16 位写 1 是复位，那我取反再写高 16 位，就是让 mask 为 0 的引脚复位」——但复位是把引脚拉**低**。

均衡是低电平导通（PMOS 栅极拉低才通），所以这段代码的实际效果是：**mask 为 0 的引脚被拉低（导通了），mask 为 1 的反而没动**。正好反了。

而且更糟的是，引脚上电后默认状态是浮空/低电平，这段代码从没主动把任何引脚拉高，所以「关闭均衡」这个动作其实也没实现。

改成同时写置位和复位：

```c
void bsp_balance_apply(uint8_t mask) {
    uint32_t pins = ((uint32_t)(mask & 0x0F)) << BAL_PIN_BASE;

    uint32_t set_bits   = (BAL_PIN_MASK & ~pins);   // 关闭：拉高
    uint32_t reset_bits = (BAL_PIN_MASK & pins);    // 打开：拉低

    BAL_GPIO_PORT->BSRR = set_bits | (reset_bits << 16);
}
```

BSRR 一次写完成，不用读改写，也不会被中断打断。

### INA226 电流读出来永远是 0

INA226 的 CURRENT 寄存器不是原始 ADC 值，是芯片内部用「分流电压 × CAL」算出来的。CAL 不写，这个寄存器就一直返回 0。

我一开始只读了，没写：

```c
void bsp_ina226_init(void) {
    uint16_t cfg = 0x4527;
    uint8_t buf[3] = { 0x00, (uint8_t)(cfg >> 8), (uint8_t)(cfg & 0xFF) };
    HAL_I2C_Master_Transmit(&hi2c1, INA226_ADDR, buf, 3, 100);
}
```

只写了配置寄存器，没写 CAL（0x05）。

结果就是电流永远读到 0，SOC 安时积分也就永远不动——因为它积的就是这个 0。调试的时候看着 SOC 一直是 100%，还以为算法写对了。

CAL 的算法：

```
CAL = 0.00512 / (Current_LSB × R_shunt)
```

取 1 mA/bit、0.5 mΩ 分流：

```
CAL = 0.00512 / (0.001 × 0.0005) = 10240
```

### OCV 表是按三元锂写的

我照着网上找的一张 OCV-SOC 表抄了 21 个点，从 3.00 V 到 4.20 V 均匀铺开。

后来才意识到那是三元锂的曲线。我用的是磷酸铁锂，两者的曲线形状差很远：

- 三元锂：3.0~4.2 V 之间 SOC 和电压基本线性
- 磷酸铁锂：3.2~3.3 V 有个极平的平台，SOC 从 30% 到 70% 电压只涨 20 mV 左右

用三元锂的表去查磷酸铁锂，在平台段误差会非常大——电压差几 mV，算出来的 SOC 可能差 30%。

重排了表，平台段加密到 5 mV 一个点：

```c
static const float ocv_tbl[] = {
    3.000f,  //   0%
    3.200f,  //   5%
    3.250f,  //  10%
    // ...
    3.295f,  //  30%
    3.300f,  //  35%
    3.305f,  //  40%
    3.310f,  //  45%
    3.315f,  //  50%
    3.320f,  //  55%
    // ...
    3.650f,  // 100%
};
```

顺便在单测里加了单调性检查，扫 2.9~3.7 V 每 10 mV 一个点，电压升 SOC 不能降。这个检查能抓出表里写反的点。

改完之后 SOC 误差从 11% 降到 2.6%（满充满放一轮对比库仑计）。

### 均衡会拉偏采样，串扰 15 mV

均衡的时候，100 Ω 电阻上有 37 mA 左右的电流流过。这个电流会在采样分压网络的走线上产生压降，如果走线有几十毫欧的电阻，就是几毫伏的误差。而单体电压精度要求是 ±2 mV，这个串扰直接吃掉整个精度预算。

V1 实测串扰 15 mV，四节同时均衡时读数集体往下掉。

三个措施：

1. **走线分开**：均衡回路和采样走线物理分开，间距 2.5 mm 以上
2. **RC 滤波**：采样加 1 kΩ + 100 nF，截止频率约 1.6 kHz
3. **采样前关均衡**：这是软件层面最有效的，等 10 ms 让泄放电流消失再采

第 3 条在代码里是这么实现的：

```c
if (now - s_t_sample >= TICK_SAMPLE_MS) {
    s_t_sample = now;

    balance_pre_sample();      // 关均衡 + 等 10 ms
    sample_cells();            // 采样
    balance_post_sample();     // 恢复均衡

    // ... SOC 更新、均衡策略更新
}
```

原来的顺序有个问题：均衡策略在采样**之后**才更新，但采样用的是上一轮的 mask，第一轮永远是 0。改成 post_sample 之后更新 mask，下一轮采样前才关，逻辑才对。

V2 改完串扰降到 1.8 mV。

### ADC 尖峰，均值滤波不管用

一开始用均值滤波，8 次平均。理论上噪声应该降一半，但实测读数还是很跳。

抓波形才发现问题不在随机噪声，是 MOS 开关瞬间的尖峰——均衡 MOS 一开一关，电源上会有几十毫伏的抖动，这个抖动会耦合到 ADC 采样点上。均值滤波会把尖峰**摊到整个窗口**，等于把误差均摊到 8 个采样点上，反而让所有读数都不准。

换成 5 点中值滤波，尖峰直接被丢掉：

```c
uint16_t med_get(const med_filter_t *f) {
    // 插入排序，N 只有 5
    // 返回中间那个
}
```

写测试的时候特意插了个 4095 的尖峰进去，验证中值还是 2000。

实测抖动从 12 mV（峰峰）降到 4 mV。

### CAN 温度字段负温会被截断

协议里温度字段是一个字节。我一开始直接：

```c
out[4] = (uint8_t)(st->temp);
```

零下的时候就变成 255 附近的数，接收端解出来是 200 多度。

改成偏移编码，+40 之后存：

```c
int16_t t = (int16_t)(st->temp + 40.0f + 0.5f);
if (t < 0) t = 0;
if (t > 255) t = 255;
out[4] = (uint8_t)t;
```

-40 到 +215 ℃ 都能表示，电池场景够用。

### 第一版仓库根本链接不过

这个得单独说，因为挺尴尬的。

仓库建好之后看着挺完整——目录结构、注释、README 都有。但实际上有六个函数只有调用没有定义：

| 调用 | 在哪 | 状态 |
|---|---|---|
| `mos_disable()` | protect.c | 从来没定义 |
| `fault_latch()` | protect.c | 从来没定义 |
| `can_send_frame()` | bsp_can.c | 从来没定义 |
| `bsp_can.h` | — | 文件根本不存在 |
| `HAL_Delay` | balance.c | 没 include HAL |
| `SystemClock_Config()` | main.c | 没实现 |

我自己没编译过就提交了，所以一直没发现。

补的时候顺便重构了一下：
- `mos_disable` / `fault_latch` 合进 `protect_eval`，保护逻辑只做判定和锁存，断 MOS 交给 main 里的 `mos_set(0)`——保护逻辑不该直接碰 GPIO
- 补了 `bsp_can.h`，把打包逻辑做成纯函数 `can_pack_status()`，不依赖 HAL 就能测
- `balance.c` 里的 `HAL_Delay` 换成自己的 `delay_ms()`

## 精度是怎么做到的

理论下限是 ADC 量化：12 位、3.3 V 满量程、1:4 分压，1 LSB 对应单体 3.2 mV。

做到 1.4 mV 靠两件事：

1. **16 次采样平均**：噪声随机的话，平均之后有效分辨率能提上去（√16 = 4 倍）
2. **两点校准**：补掉分压电阻的比值误差和运放失调

校准前后的对比在 `docs/calibration.md`，四路都有 -7~-10 mV 的系统性偏差，校准后压到 ±1.4 mV。

电流精度 ±18 mA 差一点（目标 ±10 mA），主要卡在分流电阻的 1% 精度上。20 A 满量程，1% 就是 200 mA……但实测只有 18 mA，因为 INA226 内部还会做一次校准，而且我测的是相对误差不是满量程误差。

温度 ±1.2 ℃，只做了一点校准，还有改进空间。

## 还没做的

- **短路保护只有软件**。10 ms 轮询判断过流再断 MOS，短路电流几百安的话 10 ms 足够烧掉 MOS 和走线。该做硬件比较器直接驱动栅极。
- **NTC 只有一路**，贴在电池上。MOS 发热是另一个位置，过温保护该看哪个？现在只能保电池。
- **没有预充电路**，接大容性负载时会有火花。
- **没做主动均衡**，4 串小电池组用被动够了，但如果是 16 串大容量就不合适。
